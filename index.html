Support Ticket AI

500tickets, queried in plain English

Ask questions about support tickets in natural language and get flagged anomalies back.

What it does

  • Loads support ticket data from CSV into a SQLite database with Pandas.
  • Turns a natural-language question into a SQL SELECT query using a Groq LLM, then runs it and shows the result table.
  • Detects unusually long resolution times with the IQR method (upper limit = Q3 + 1.5 x IQR).
  • Flags Critical tickets that stayed unresolved for more than 24 hours.
  • FastAPI backend with 3 endpoints (health, query, anomalies) and a Streamlit UI that shows results, the generated SQL, and anomaly counts.

How it works

CSVPandas ingestionSQLiteGroq LLM to SQLFastAPIStreamlit UI

Design decisions

  • The LLM only writes the SQL. Anomaly detection and all numbers come from deterministic Python and SQL, so results are reproducible and explainable.
  • Read-only safety: generated SQL must start with SELECT, only the support_tickets table is exposed, and INSERT, UPDATE, DELETE, DROP and ALTER are blocked. Result rows are capped.
  • Clear errors for invalid SQL and for an unreachable backend.

Tools

PythonPandasSQLiteSQLFastAPIStreamlitGroq LLMPydantic
View on GitHub

Try these questions

  • How many tickets are currently open? (returns 111)
  • Which agent resolved the most tickets this month?
  • Show me all Critical tickets not resolved within 12 hours.
  • What is the average customer rating for Technical category tickets?

Dataset

  • 500 tickets with category (Billing, Technical, General), priority (Low to Critical), status, response and resolution times, agent, rating, and issue summary.
